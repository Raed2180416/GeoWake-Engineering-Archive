## Core data and decision lineage

- **Destination record** (`description`, optional `place_id`, latitude/longitude) originates from local recent suggestions, Places details or map tap (`lib/screens/homescreen.dart:335-418`); Home may remap it to a metro stop before routing (`homescreen.dart:703-741`). Recent destinations live in Hive; automatic route memory is a different Hive box (`lib/screens/otherimpservices/recent_locations_service.dart:4-77`; `lib/services/saved_routes_service.dart:17-33`).
- **Directions JSON** flows through `OfflineCoordinator` and `DirectionService` to Home, snapshot and `RouteSessionManager` (`homescreen.dart:744-790,983-995,1087-1129`; `route_session_manager.dart:151-173,775-847`). Route geometry, cumulative meters, stops, events and switch points feed both map display and the alarm's meter/stop domain. This pipeline is useful for AI evaluation because the same route can be studied from provider JSON through derived state and decisions.
- **Alarm contract** (`alarmMode`, numeric `alarmValue`, `transitMode`) is chosen in Home and copied to background start, snapshot, map arguments and reroute constraints (`homescreen.dart:805-816,983-1044,1114-1129`; `tracking_state_store.dart:13-87`; `reroute_constraints.dart:31-55`). B stop-mode arming and reroute validation use different code paths; the captured local fixes add a shared validator. Treat any statement that thresholds are consistent across all legs as a hypothesis unless testing the captured changes separately.
- **Position and uncertainty** move from `LocationManager` to route snap/EKF and `AlarmController`; route-keyed fired IDs prevent repeated alerts and migrate at switches (`lib/services/location_manager.dart:205-344`; `lib/services/tracking/alarm_controller.dart:203-245,1495-1575`; `lib/services/trackingservice.dart:1720-1728`). `Reachability` computes an upper possible progress from a trusted anchor and speed ceiling (`lib/core/reachability/reachability.dart:15-45,531-631`).

## Evidence quality, limitations and historical interpretation

1. The committed deterministic corpus has **3 replay headers and 15 scale headers; all 18 have `synthetic: true`** (`test/fixtures/replay/fixture_*.json:1-10`; `test/fixtures/scale/*/base.json:1-18`). City and ride names are scenario labels, not proof that the bundled IMU/GPS streams are measured rides. `tools/make_replay_fixtures.py:1-40` points to larger external inputs under `/home/developer/geowake_imu_analysis/fixtures`; they are not part of this repository. The `REAL underground ride` test explicitly returns when no non-synthetic underground fixture exists (`test/ekf/replay_harness_test.dart:1202-1224`). Comments and `docs/research/underground/ON_ROUTE_CONFIRMATION.md:1-26` discuss two handheld rides and derived research, but their source data/scripts are external to this sale tree. `docs/research/underground/ON_ROUTE_CONFIRMATION.md:228-242` labels signed cross-track and on-train confirmation as extensions to existing code, not completed modules.
2. **“Never-late” is a conditional algorithmic invariant, not a phone alarm guarantee.** The reachability source lists its preconditions: accepted real anchor, speed ceiling not below actual speed, and elapsed time since the real fix (`lib/core/reachability/reachability.dart:15-45`). The first-use disclaimer explicitly warns OS/battery/DND conditions can delay or silence delivery (`lib/screens/homescreen.dart:581-595`). Dynamic reachability levers default off and curve trust defaults false (`lib/core/reachability/reachability.dart:419-448`). The synthetic replay/scale gates show deterministic code behavior; they do not measure background survival or actual rider wake timing.
3. `test/tracking_service_reroute_integration_test.dart:76-150` uses two constructed perpendicular lines and injected GPS. It is evidence of wiring and state transitions, not measured deviation precision. Baseline `SnapToRouteEngine` accepts `previousResult`, but `ActiveRouteManager._snapTo` supplies only a segment hint (`lib/services/snap_to_route.dart:39-50`; `lib/services/active_route_manager.dart:327-334`), leaving crossing continuity work to P. Baseline route registration is fire-and-forget and tracking ACK can degrade to a blind invoke (`lib/screens/homescreen.dart:1087-1108`; `lib/services/trackingservice.dart:341-376`). Those are valuable characterized failure cases in the corpus.
4. Historical commits are provenance, not independent test receipts: `8f5601f` route cache/Places session behavior; `975028e` deviation and GPS-health checkpoint; `681bb4d` background preboarding-toggle reload; `c3f81ff` ETA/transfer overhaul; `2d51f24` first never-late CI gate; `b6158e5` monotonic-clock fix; `a25f59e` arrival hooks; `b1b30f5` underground validation commit.
